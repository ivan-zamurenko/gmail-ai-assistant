## Не входит

Нет нового backend, обхода авторизации intranet, отправки session в logs или расширения доступа на все сайты.

## Критерии приёмки

1. Отсутствующая вкладка, чужой host, неподходящий protocol/path и URL без требуемого контекста отклонены до executeScript.
2. Допустимый target определяется явной конфигурацией и контрактом, а не поиском подстроки interlink в произвольном URL.
3. Form action другого origin отклонён до передачи hidden fields/session; относительный action безопасно разрешается от проверенной базы.
4. Смена вкладки/навигация между preview и apply обнаруживается повторной проверкой, а не только disabled button.
5. Сериализованный injected function запускается без outer imports и получает только явно разрешённые args.

## Test-first и команды

Негативные fixtures текущего getActiveTab и hostile form action должны показать отсутствие нужного отказа; реальная рабочая вкладка не используется.

```sh
node --test test/unit/depot-target.test.mjs
```

Виконано 2026-10-23: `node --test --import ./test/helpers/noNetwork.js test/depot/depotTarget.test.js test/depot/depotScript.test.js test/depot/lookup.test.js test/queue/executor.test.js`
(модульна структура `test/`). Scope розширено: `src/depot/depotTarget.js`,
`src/queue/executor.js` (повторна перевірка вкладок) і, за рішенням власника,
перенесення POD з MAIN (`src/depot/podImage.js`).

Это целевая команда карточки: указанные product test files нужно создать при её выполнении. Их нет в исходном ZIP, и они не объявлены пройденными. Сначала подготовить harness по зависимостям. При изменении имени теста обновить карточку и evidence до заявления о GREEN.

После узкой проверки выполнить затронутые регрессии и обязательные lint/build проверки по [toolchain](../../docs/toolchain.md). Для injected code отдельно проверять serialization, для UI — реальный browser harness. Не выполнять real Gmail/Drive/depot/AI calls по одному разрешению редактировать код.

## Последовательность реализации

1. Сформировать allowlist/validation boundary без расширения существующего доменного scope.
2. Написать URL, navigation и serialized-function tests.
3. Подключить guard перед injection и перед изменяющей отправкой.

## Контракт данных и побочных эффектов

Session-bearing данные остаются внутри проверенного depot origin. Не расширять manifest host_permissions ради прохождения теста. Chrome MAIN world не считается доверенным sandbox.

Новый SQL/серверный стек не вводится: сохраняются Chrome + существующий Node bot + Firestore. Изменения config/queue/storage требуют явной совместимости и recovery; не создавать несуществующий src/storage по старому шаблону. Правила безопасности: [security](../../docs/security-and-privacy.md), [контракты](../../docs/contracts.md).
