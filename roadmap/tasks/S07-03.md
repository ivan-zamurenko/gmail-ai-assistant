## Не входит

Нет полной смены дизайна, незаказанной локализации, новых UI framework или заявления о формальной сертификации доступности.

## Критерии приёмки

1. Все значимые действия доступны клавиатурой, имеют label и видимый focus; focus не теряется после error/preview.
2. Progress/error announcements доступны assistive technology и не повторяют приватное содержимое в live region.
3. Длинные reason/filename и маленький viewport не скрывают подтверждение/cancel за неконтролируемым overflow.
4. Disabled/pending кнопки имеют объяснимое состояние, но domain guards остаются в command layer.
5. Язык интерфейса не меняется из-за русского языка документации; тексты согласованы с существующим UI и решением владельца.

## Test-first и команды

Сначала browser assertions keyboard/focus/error и overflow fixtures; отсутствие Chrome отмечать env_blocked, не заменять screenshot claim.

```sh
node --test test/browser/popup-accessibility.test.mjs
```

Это целевая команда карточки: указанные product test files нужно создать при её выполнении. Их нет в исходном ZIP, и они не объявлены пройденными. Сначала подготовить harness по зависимостям. При изменении имени теста обновить карточку и evidence до заявления о GREEN.

После узкой проверки выполнить затронутые регрессии и обязательные lint/build проверки по [toolchain](../../docs/toolchain.md). Для injected code отдельно проверять serialization, для UI — реальный browser harness. Не выполнять real Gmail/Drive/depot/AI calls по одному разрешению редактировать код.

## Последовательность реализации

1. Перечислить основные interactive controls и error states.
2. Добавить keyboard/focus/browser cases.
3. Исправить markup/style точечно и проверить неизменность behavior.

## Контракт данных и побочных эффектов

Accessibility проверяется действиями и DOM semantics, не только визуальным видом. Смена CSS не должна пересоздавать job или очищать unsaved config.

Новый SQL/серверный стек не вводится: сохраняются Chrome + существующий Node bot + Firestore. Изменения config/queue/storage требуют явной совместимости и recovery; не создавать несуществующий src/storage по старому шаблону. Правила безопасности: [security](../../docs/security-and-privacy.md), [контракты](../../docs/contracts.md).
