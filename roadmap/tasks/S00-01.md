> **Адаптація до робочого проєкту, 2026-10-23.** Поточний стан і пріоритет рішень: [LOCAL_BASELINE](../../docs/audit/LOCAL_BASELINE.md). Нижче збережено план комплекту v1.2; його вихідний ZIP і старі перевірки не є поточним checkout. Майбутні задачі не запускаються автоматично. Спілкування з власником — українською.


**Одна задача:** Установить фактический checkout и аккуратно подключить комплект, не перезаписывая чужую работу и не создавая приложение заново.

## Прочитать для этой задачи

- `INSTALL_RU.md`
- `docs/audit/GITHUB_BASELINE.md`
- `docs/decisions.md`

Начать с применимых `AGENTS.md` и `.workflow/CURRENT.md`. Пути `src/` относятся к исходному репозиторию: runtime не вложен в ZIP документации. Некоторые модули/документы будущих задач будут созданы зависимостями. Не объявлять отсутствие будущего файла поломкой исходного проекта. Команда `node tools/roadmap.mjs context S00-01` показывает наличие путей в текущем checkout.

## Не входит

Нет смены стека, npm update, массового переноса src, нового origin и push.

## Критерии приёмки

1. При существующем README и заполненном CURRENT сначала записан узкий diff; оба файла не заменяются автоматически шаблоном.
2. Наличие Git и фактическая ветка установлены в рабочей папке. Архивный SHA не объявлен текущим HEAD без проверки; credentials remote не выводятся.
3. Отсутствие Git не приводит к git init в неизвестной папке. Решение об инициализации отдельно подтверждено и записано.
4. После объединения next возвращает S00-01 как текущую первую задачу; validation не падает из-за потерянных скрытых каталогов.
5. Чужие изменения, сохранённый старый README и пути с приватными данными перечислены без содержимого; original runtime не удалён.

## Test-first и команды

Для tooling использовать реальную проверку отсутствующего/повреждённого файла в одноразовой копии. Если комплект уже корректно установлен, записать baseline GREEN и N/A для RED; не портить основной checkout ради красного теста.

```sh
node tools/roadmap.mjs validate && node tools/check-docs.mjs && node --test tools/tests/*.test.mjs
```

Команда уже существует в комплекте. Она проверяет документы/tooling, а не заменяет ручную или внешнюю проверку, описанную ниже.

После узкой проверки выполнить затронутые регрессии и обязательные lint/build проверки по [toolchain](../../docs/toolchain.md). Для injected code отдельно проверять serialization, для UI — реальный browser harness. Не выполнять real Gmail/Drive/depot/AI calls по одному разрешению редактировать код.

## Последовательность реализации

1. Проверить корень, git status и только относящийся к установке diff.
2. Сопоставить архивную инвентаризацию с реальным checkout; записать расхождения.
3. Объединить только прочитанные файлы по INSTALL_RU.md и выполнить проверки комплекта.

## Контракт данных и побочных эффектов

API и chrome.storage не меняются. Единственный эффект — согласованная документация и зафиксированное локальное состояние. Remote, identity и приложение сохраняются.

Новый SQL/серверный стек не вводится: сохраняются Chrome + существующий Node bot + Firestore. Изменения config/queue/storage требуют явной совместимости и recovery; не создавать несуществующий src/storage по старому шаблону. Правила безопасности: [security](../../docs/security-and-privacy.md), [контракты](../../docs/contracts.md).

## Критерий завершения

Все сценарии выше проверены на указанном уровне; одна лишь проверка Markdown не закрывает product acceptance. Нет ослабленных expectations, пустых успешных suites и skip вместо обязательной проверки. В evidence сохранены точные команды, cwd, exit codes, граница synthetic/live, непроверенное и остаточный риск. Если не хватает решения или среды, записать blocked/env_blocked и конкретный следующий шаг; не ставить done.

## Review, commit и передача

Проверить `git status --short`, узкий diff и `git diff --check`; staging только просмотренных путей. Разрешение commit/push сверить отдельно. Предложенный subject:

```text
docs(workflow): [S00-01] adopt existing project baseline
```

Evidence: `.workflow/evidence/S00-01.json`. Обновить существующие CURRENT/state, не заменять их шаблоном. Собственный SHA не записывать внутрь создаваемого коммита. В финале указать фактические RED/GREEN или честное N/A, commit/push status и один следующий task ID.

## Адаптация к bot baseline v1.2

Принять именно последний GitHub ZIP: он содержит bot/Firestore/offscreen и не содержит .git. Исторические commit SHA и dirty tree первого ZIP не подставлять как актуальные. Сохранить существующие docs/SECURITY.md и поточні product tests; сверить фактический checkout.
