## Не входит

Нет универсального SDK framework, неограниченного exponential retry, live quota tests или сокрытия 403.

## Критерии приёмки

1. 401 и 403 с insufficient permissions дают разные коды; generic 403 не превращается автоматически в refresh-token loop.
2. 429/503 для безопасного read имеют ограниченное число attempts, timeout и cancellable ожидание; исчерпание бюджета видно в результате.
3. Timeout после отправленного PATCH/POST mutation становится uncertain и не повторяется автоматически без reconcile.
4. Per-file error сохраняется в итоговом summary и не превращает весь run в безусловный success.
5. Aborted request не помечает remote effect rolled back; error payload проходит redaction.

## Последовательность реализации

1. Определить небольшой error DTO и attempts budget как engineering defaults.
2. Зафиксировать таблицу response-to-error тестами.
3. Подключить адаптеры без blanket retry и проверить partial summaries.

## Контракт данных и побочных эффектов

Operation semantics определяют retry, не один HTTP method. Auth refresh ограничен и не меняет scopes. Shared transport создаётся только в реально повторяющихся границах.

Новый SQL/серверный стек не вводится: сохраняются Chrome + существующий Node bot + Firestore. Изменения config/queue/storage требуют явной совместимости и recovery; не создавать несуществующий src/storage по старому шаблону. Правила безопасности: [security](../../docs/security-and-privacy.md), [контракты](../../docs/contracts.md).
