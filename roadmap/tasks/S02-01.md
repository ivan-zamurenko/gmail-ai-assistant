## Не входит

Нет AI/OCR fallback, benchmark приватных фото, нового формата от стороннего перевозчика или обещания 100% распознавания.

## Критерии приёмки

1. Для каждого поддерживаемого формата указаны обязательные поля и ожидаемые consignment/parcel; неполный payload не заполняется догадкой.
2. Payload неправильной длины, с неподдерживаемым prefix и мусором вокруг отклоняется либо возвращает явный unknown согласно контракту.
3. Повторное чтение одного штрихкода не создаёт второй parcel и не усиливает достоверность другого номера без зафиксированного правила.
4. Legacy labelParser и текущий labelBarcode сравниваются на одном корпусе; различия документируются, а не скрываются заменой regex.
5. Тесты raw payload не называются проверкой camera/image decoder accuracy; реальных labels_example в fixtures нет.

## Test-first и команды

Добавить table-driven cases известного текущего parser и отдельно ожидаемые отказы malformed payload. Новые неподтверждённые форматы не включать как требование.

```sh
node --test test/unit/barcode-formats.test.mjs
```

Это целевая команда карточки: указанные product test files нужно создать при её выполнении. Их нет в исходном ZIP, и они не объявлены пройденными. Сначала подготовить harness по зависимостям. При изменении имени теста обновить карточку и evidence до заявления о GREEN.

После узкой проверки выполнить затронутые регрессии и обязательные lint/build проверки по [toolchain](../../docs/toolchain.md). Для injected code отдельно проверять serialization, для UI — реальный browser harness. Не выполнять real Gmail/Drive/depot/AI calls по одному разрешению редактировать код.

## Последовательность реализации

1. Прочитать фактические format branches и сравнить с legacy parser.
2. Составить synthetic corpus по каждой ветке и негативные границы.
3. Уточнить validation без расширения поддерживаемых форматов по догадке.

## Контракт данных и побочных эффектов

Decoder output, parsed identifiers и business validity — разные стадии. Число повторов чтения не доказывает привязку к конкретной фотографии или заказу.

Новый SQL/серверный стек не вводится: сохраняются Chrome + существующий Node bot + Firestore. Изменения config/queue/storage требуют явной совместимости и recovery; не создавать несуществующий src/storage по старому шаблону. Правила безопасности: [security](../../docs/security-and-privacy.md), [контракты](../../docs/contracts.md).
