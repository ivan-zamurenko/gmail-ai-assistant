## Не входит

Нет auto-merge, deploy, покупки runner, разрешения широких GitHub permissions или притворного зелёного cloud run.

## Критерии приёмки

1. CI вызывает те же команды, которые доступны локально; обязательный неуспешный subprocess завершает pipeline ошибкой.
2. Пустой набор unit tests не проходит; отсутствующий browser executable отмечается отдельно, а не silently skip обязательной job.
3. Права workflow минимальны, production secrets и автоматический deploy отсутствуют; dependency install использует lockfile.
4. Изменённый lockfile или отсутствующий manifest artifact обнаруживается проверкой.
5. Наличие YAML не называется работающим GitHub CI: до фактического run статус cloud execution остаётся непроверенным.

## Test-first и команды

Проверить runner на заглушке команды с exit 7: он должен вернуть ненулевой код и не напечатать общий GREEN.

```sh
node --test test/tooling/checks.test.mjs
```

Это целевая команда карточки: указанные product test files нужно создать при её выполнении. Их нет в исходном ZIP, и они не объявлены пройденными. Сначала подготовить harness по зависимостям. При изменении имени теста обновить карточку и evidence до заявления о GREEN.

После узкой проверки выполнить затронутые регрессии и обязательные lint/build проверки по [toolchain](../../docs/toolchain.md). Для injected code отдельно проверять serialization, для UI — реальный browser harness. Не выполнять real Gmail/Drive/depot/AI calls по одному разрешению редактировать код.

## Последовательность реализации

1. Собрать команды предыдущих карточек в явный runner.
2. Протестировать fail-fast/обязательность стадий и отсутствие секретов.
3. Добавить read-only CI; зафиксировать подтверждённые версии внешних Actions при реализации.

## Контракт данных и побочных эффектов

CI не авторизует Drive/depot/Gmail, не загружает клиентские fixtures и не делает release. Локальный success и удалённый run имеют раздельные evidence.

Новый SQL/серверный стек не вводится: сохраняются Chrome + существующий Node bot + Firestore. Изменения config/queue/storage требуют явной совместимости и recovery; не создавать несуществующий src/storage по старому шаблону. Правила безопасности: [security](../../docs/security-and-privacy.md), [контракты](../../docs/contracts.md).

## Критерий завершения

Все сценарии выше проверены на указанном уровне; одна лишь проверка Markdown не закрывает product acceptance. Нет ослабленных expectations, пустых успешных suites и skip вместо обязательной проверки. В evidence сохранены точные команды, cwd, exit codes, граница synthetic/live, непроверенное и остаточный риск. Если не хватает решения или среды, записать blocked/env_blocked и конкретный следующий шаг; не ставить done.

## Review, commit и передача

Проверить `git status --short`, узкий diff и `git diff --check`; staging только просмотренных путей. Разрешение commit/push сверить отдельно. Предложенный subject:

```text
ci(checks): [S00-04] enforce local quality gates
```

Evidence: `.workflow/evidence/S00-04.json`. Обновить существующие CURRENT/state, не заменять их шаблоном. Собственный SHA не записывать внутрь создаваемого коммита. В финале указать фактические RED/GREEN или честное N/A, commit/push status и один следующий task ID.

## Адаптация к bot baseline v1.2

CI устанавливает оба locks, запускает старый security suite и новые тесты; не имеет production credentials и не выполняет Discord register, bot start или Firestore deploy. Bot tests и docs tooling не выдаются за реальные внешние проверки.
