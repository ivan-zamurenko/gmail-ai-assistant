## Не входит

Нет удаления пользовательского ключа, новой cloud БД, автоматической ротации identity или запроса secrets в чате.

## Критерии приёмки

1. Отсутствующий или placeholder обязательный bot config приводит к безопасному отказу до login/queue; partial optional Maps config не требует bot credentials в extension.
2. Существующие local.js не перезаписываются при подготовке; serviceAccountPath разрешается относительно bot root. Миграция не удаляет чужие поля/legacy данные автоматически.
3. Discord token и Firebase service-account secret не попадают в browser bundle, diagnostics или snapshots; тест использует marker values, не реальные keys.
4. Folder input и config shape валидируются до внешнего обращения. Статический src/config import документирован; не утверждать, что gitignore исключает встроенные bundle values.
5. Manifest identity и gmail.readonly scopes не заменяются автоматически. Наличие geminiApiKey не объявляется подключённым AI, а settingsFlow без caller не объявляется рабочим UI.

## Test-first и команды

Сначала fixture config/module loader без сетевого startup: отсутствие обязательных полей, безопасные ошибки и проверка границы bundle secrets. Ошибка отсутствующего real local.js не выдаётся за functional RED.

```sh
node --test test/unit/config-boundaries.test.mjs
```

Это целевая команда карточки: указанные product test files нужно создать при её выполнении. Их нет в исходном ZIP, и они не объявлены пройденными. Сначала подготовить harness по зависимостям. При изменении имени теста обновить карточку и evidence до заявления о GREEN.

После узкой проверки выполнить затронутые регрессии и обязательные lint/build проверки по [toolchain](../../docs/toolchain.md). Для injected code отдельно проверять serialization, для UI — реальный browser harness. Не выполнять real Gmail/Drive/depot/AI calls по одному разрешению редактировать код.

## Последовательность реализации

1. Сверить оба config.js и local.example.js, а также фактических callers.
2. Написать negative config/bundle boundary tests на synthetic markers.
3. Минимально валидировать конфигурацию, не вводя новый settings backend или второй storage layer.

## Контракт данных и побочных эффектов

Действующий источник config и стратегия совместимости документируются до изменения keys. Наличие OAuth scope не является разрешением на бизнес-эффект.

Новый SQL/серверный стек не вводится: сохраняются Chrome + существующий Node bot + Firestore. Изменения config/queue/storage требуют явной совместимости и recovery; не создавать несуществующий src/storage по старому шаблону. Правила безопасности: [security](../../docs/security-and-privacy.md), [контракты](../../docs/contracts.md).
