## Не входит

Нет автоматического отката чужих remote изменений, удаления всех журналов, бесконечных retries или утверждения cancel=rollback.

## Критерии приёмки

1. Два popup не становятся двумя writers одного job; ownership/lease потеря обнаруживается до очередного effect.
2. Item transitions planned/applying/applied/failed/uncertain сохраняются до следующего шага, а restart не считает applying завершённым.
3. Timeout после фактически выполненного PATCH сначала проверяется remote metadata; повтор не создаёт дополнительную папку/rename suffix.
4. Cancel останавливает выдачу новой работы и честно сохраняет уже выполненные effects; pending request не объявляется отменённым на сервере без подтверждения.
5. Журнал содержит минимум данных, не Google token, raw image или полный depot session URL; cleanup не удаляет историю неопределённого результата до решения.

## Test-first и команды

Fault injection между каждым durable write/network step, включая accepted-but-lost response; проверять число эффектов после restart.

```sh
node --test test/integration/drive-recovery.test.mjs
```

Это целевая команда карточки: указанные product test files нужно создать при её выполнении. Их нет в исходном ZIP, и они не объявлены пройденными. Сначала подготовить harness по зависимостям. При изменении имени теста обновить карточку и evidence до заявления о GREEN.

После узкой проверки выполнить затронутые регрессии и обязательные lint/build проверки по [toolchain](../../docs/toolchain.md). Для injected code отдельно проверять serialization, для UI — реальный browser harness. Не выполнять real Gmail/Drive/depot/AI calls по одному разрешению редактировать код.

## Последовательность реализации

1. Зафиксировать разрешённые transitions и recovery для каждого состояния.
2. Добавить fault/restart/cancel/concurrency tests.
3. Подключить reconciler и вывести uncertain outcomes оператору.

## Контракт данных и побочных эффектов

Single writer и local operation key снижают дубли, но внешнее exactly-once не обещается. Journal retention для реальных данных требует G_PRIVACY.

Новый SQL/серверный стек не вводится: сохраняются Chrome + существующий Node bot + Firestore. Изменения config/queue/storage требуют явной совместимости и recovery; не создавать несуществующий src/storage по старому шаблону. Правила безопасности: [security](../../docs/security-and-privacy.md), [контракты](../../docs/contracts.md).
