## Не входит

Нет покупки доступа, выбора модели по бренду из образца, загрузки писем/фото или утверждения что AI уже подключён.

## Критерии приёмки

1. В decision указаны provider, model capability, разрешённая цель, payload fields и budget; версии API перепроверены по официальной документации.
2. Неактивный provider не делает network requests и не требует secrets; fake implementation помечена как fake.
3. Adapter имеет explicit timeout/error/cancel contract, а retry не создаёт неограниченные платные обращения.
4. Token/API key не оказывается в MAIN world, logs, shared exports или клиентском текстовом prompt.
5. Unknown configuration и превышенный budget приводят к blocked outcome до запроса, без fallback на другого платного provider.

## Test-first и команды

Сначала contract tests disabled/missing-config/budget/timeout. Не обращаться к настоящей модели для получения TDD RED.

```sh
node --test test/unit/ai-provider-contract.test.mjs
```

Это целевая команда карточки: указанные product test files нужно создать при её выполнении. Их нет в исходном ZIP, и они не объявлены пройденными. Сначала подготовить harness по зависимостям. При изменении имени теста обновить карточку и evidence до заявления о GREEN.

После узкой проверки выполнить затронутые регрессии и обязательные lint/build проверки по [toolchain](../../docs/toolchain.md). Для injected code отдельно проверять serialization, для UI — реальный browser harness. Не выполнять real Gmail/Drive/depot/AI calls по одному разрешению редактировать код.

## Последовательность реализации

1. Записать утверждённый provider/payload/budget и границу secret storage.
2. Написать adapter contract tests на synthetic transport.
3. Реализовать минимальный adapter без live calls и автоматической миграции ключей.

## Контракт данных и побочных эффектов

Provider choice остаётся решением владельца, gate approve не равен проверенному live access. Модель выдаёт proposal, не команды Google/depot.

Новый SQL/серверный стек не вводится: сохраняются Chrome + существующий Node bot + Firestore. Изменения config/queue/storage требуют явной совместимости и recovery; не создавать несуществующий src/storage по старому шаблону. Правила безопасности: [security](../../docs/security-and-privacy.md), [контракты](../../docs/contracts.md).
