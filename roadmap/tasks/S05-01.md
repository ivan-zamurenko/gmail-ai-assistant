## Не входит

Нет автосоздания labels, чтения body, AI calls, отправки сообщений или произвольной обработки всего Inbox.

## Критерии приёмки

1. Две/три страницы с nextPageToken возвращают все уникальные message IDs, не только первую страницу.
2. Отсутствующая метка, пустая очередь и отказ Gmail API имеют разные состояния; пустой результат не маскирует 403.
3. Повторяющийся token, duplicate ID и превышенный configured limit обработаны без бесконечного цикла.
4. UI не называет resultSizeEstimate точным числом обработанных сообщений; partial enumeration отображается явно.
5. Чтение очереди не создаёт/снимает метки, drafts и письма; тест проверяет отсутствие mutations.

## Test-first и команды

Fixture первая страница с nextPageToken и вторая с дополнительным ID воспроизводит текущий неполный результат labels.js.

```sh
node --test test/unit/gmail-pagination.test.mjs
```

Это целевая команда карточки: указанные product test files нужно создать при её выполнении. Их нет в исходном ZIP, и они не объявлены пройденными. Сначала подготовить harness по зависимостям. При изменении имени теста обновить карточку и evidence до заявления о GREEN.

После узкой проверки выполнить затронутые регрессии и обязательные lint/build проверки по [toolchain](../../docs/toolchain.md). Для injected code отдельно проверять serialization, для UI — реальный browser harness. Не выполнять real Gmail/Drive/depot/AI calls по одному разрешению редактировать код.

## Последовательность реализации

1. Написать multi-page, missing-label и token-loop cases.
2. Добавить bounded pagination и deduplication.
3. Передать точный/частичный status в gmailFlow без запуска обработки.

## Контракт данных и побочных эффектов

Queue enumeration — read-only. Метка AI-Reply пока наблюдаемый default кода, не подтверждённая финальная lifecycle policy.

Новый SQL/серверный стек не вводится: сохраняются Chrome + существующий Node bot + Firestore. Изменения config/queue/storage требуют явной совместимости и recovery; не создавать несуществующий src/storage по старому шаблону. Правила безопасности: [security](../../docs/security-and-privacy.md), [контракты](../../docs/contracts.md).
