## Не входит

Нет обновления всех зависимостей, публикации в store, загрузки реальных накладных или смены ключа manifest.

## Критерии приёмки

1. В чистой временной рабочей копии root npm ci и npm --prefix bot ci используют оба существующих lockfile; ни один lockfile не меняется незаметно.
2. Одноразовая сборка создаёт все entry points manifest, popup, offscreen и console lookup; source marker не попадает в рабочее имя dist.
3. Watch при изменении lookup обновляет тот же console artifact, что разовая сборка; текущий пропуск build.js воспроизведён тестом.
4. Очистка dist ограничена каталогом сборки и не удаляет assets/src/данные; ошибка сборки сохраняет ненулевой exit code.
5. Версии Node/npm/esbuild и проверенные команды зафиксированы фактически. Установка из архивного node_modules не названа clean install.

## Test-first и команды

Сначала тест отсутствующего или не обновляющегося console bundle в watch и проверка границы очистки dist; существующий build используется как baseline.

```sh
node --test test/tooling/build.test.mjs
```

Это целевая команда карточки: указанные product test files нужно создать при её выполнении. Их нет в исходном ZIP, и они не объявлены пройденными. Сначала подготовить harness по зависимостям. При изменении имени теста обновить карточку и evidence до заявления о GREEN.

После узкой проверки выполнить затронутые регрессии и обязательные lint/build проверки по [toolchain](../../docs/toolchain.md). Для injected code отдельно проверять serialization, для UI — реальный browser harness. Не выполнять real Gmail/Drive/depot/AI calls по одному разрешению редактировать код.

## Последовательность реализации

1. Зафиксировать установленную среду и прочитать lifecycle/build scripts до npm ci.
2. Добавить тест состава и обновления артефактов, воспроизвести watch drift.
3. Исправить единый build plan и документировать воспроизводимую установку.

## Контракт данных и побочных эффектов

Публичная extension identity не меняется. Build output остаётся dist; runtime не получает новый framework. Поддерживаемая версия Node выбирается по реально успешной установке, не копируется из чужого проекта.

Новый SQL/серверный стек не вводится: сохраняются Chrome + существующий Node bot + Firestore. Изменения config/queue/storage требуют явной совместимости и recovery; не создавать несуществующий src/storage по старому шаблону. Правила безопасности: [security](../../docs/security-and-privacy.md), [контракты](../../docs/contracts.md).

## Критерий завершения

Все сценарии выше проверены на указанном уровне; одна лишь проверка Markdown не закрывает product acceptance. Нет ослабленных expectations, пустых успешных suites и skip вместо обязательной проверки. В evidence сохранены точные команды, cwd, exit codes, граница synthetic/live, непроверенное и остаточный риск. Если не хватает решения или среды, записать blocked/env_blocked и конкретный следующий шаг; не ставить done.

## Review, commit и передача

Проверить `git status --short`, узкий diff и `git diff --check`; staging только просмотренных путей. Разрешение commit/push сверить отдельно. Предложенный subject:

```text
build(toolchain): [S00-02] make extension builds reproducible
```

Evidence: `.workflow/evidence/S00-02.json`. Обновить существующие CURRENT/state, не заменять их шаблоном. Собственный SHA не записывать внутрь создаваемого коммита. В финале указать фактические RED/GREEN или честное N/A, commit/push status и один следующий task ID.

## Адаптация к bot baseline v1.2

Две установки: root npm ci и npm --prefix bot ci, два lockfile. Сборка включает offscreen. src/config/local.js отсутствует в архиве и статически импортируется: synthetic build config готовить отдельно без перезаписи и без bot secrets. Не запускать bot start/register в build tests.
