## Не входит

Нет автоматической отправки, production rollout, обучения модели на почте или заявления об универсальной точности.

## Критерии приёмки

1. Перед вызовами подтверждены конкретные payload, модель, бюджет и synthetic/redacted dataset; credentials не передаются через чат.
2. Реальные latency/errors/structured output записаны отдельно от fake tests и без raw customer contents.
3. Shadow output проходит schema/evaluator и доступен только для review; downstream effects отсутствуют.
4. Rate limit, timeout и budget exhaustion остановлены ограниченно; не включается запасная модель с неожиданной оплатой.
5. Неуспешные критические cases остаются открытыми и блокируют допуск; отсутствие стенда даёт env_blocked, не passed.

## Test-first и команды

Внешняя проверка не требует искусственно тратить запрос ради RED. Checklist и pass/fail rubric фиксируются до запуска; фактические failures сохраняются.

```sh
node tools/roadmap.mjs validate && node tools/check-docs.mjs
```

Команда уже существует в комплекте. Она проверяет документы/tooling, а не заменяет ручную или внешнюю проверку, описанную ниже.

После узкой проверки выполнить затронутые регрессии и обязательные lint/build проверки по [toolchain](../../docs/toolchain.md). Для injected code отдельно проверять serialization, для UI — реальный browser harness. Не выполнять real Gmail/Drive/depot/AI calls по одному разрешению редактировать код.

## Последовательность реализации

1. Сверить scopes и ограничения расходов с владельцем.
2. Выполнить разрешённый shadow batch по rubric.
3. Сохранить агрегированные результаты и решение о допустимом следующем использовании.

## Контракт данных и побочных эффектов

Shadow разрешает только ограниченные model calls. Это не разрешение auto-send, reschedule или обработки произвольных клиентских документов.

Новый SQL/серверный стек не вводится: сохраняются Chrome + существующий Node bot + Firestore. Изменения config/queue/storage требуют явной совместимости и recovery; не создавать несуществующий src/storage по старому шаблону. Правила безопасности: [security](../../docs/security-and-privacy.md), [контракты](../../docs/contracts.md).
