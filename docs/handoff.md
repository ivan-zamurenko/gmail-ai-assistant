Актуальний протокол для всіх клієнтів: [AGENT_ASSIGNMENTS](AGENT_ASSIGNMENTS.md).
Один writer у спільному checkout, явна передача сесії через CURRENT;
паралельно — read-only аналіз і review.

## Канонические файлы

`.workflow/CURRENT.md` — короткий фактический checkpoint. `.workflow/state.json` — машинные статусы/gates. `.workflow/evidence/<TASK>.json` — проверяемые результаты конкретной карточки. `CURRENT.template.md` — только образец; не копировать поверх заполненного состояния.

Документы не заменяют реальное дерево Git. Новая сессия сверяет branch/base SHA, status и существование файлов. Старый checkpoint может отстать от checkout после ручных изменений.

## Что записывать

Task ID и scope, статус, реальная ветка, baseline SHA до работы, последний существующий commit после проверки, изменённые пути, чужие изменения, RED/GREEN команды/exit codes, regressions, невыполненные проверки, blocker, rejected hypotheses, residual risk и один ближайший шаг.

Не писать реальный OAuth token, полный remote URL с credentials, depot session URL, письмо, address, label photo или HTML dump. Evidence содержит результаты, а не копию клиентских данных.

## Статусы

`todo` — работа не начиналась. `in_progress` — есть активная задача. `blocked` — не хватает решения/зависимости. `env_blocked` — не хватает проверяемого окружения/допуска. `done` — выполнены все критерии карточки и заполнено evidence; это не автоматическое production approval.

State допускает не более одной `in_progress` задачи. `active_task` должен совпадать с ней. Для blocked/env_blocked обязательна причина; для done обязательна ссылка на evidence. Gate `approved` требует основания. Selector не меняет эти поля автоматически.

## На границе задачи

Сверить факты → записать evidence → обновить state/CURRENT → review → разрешённый commit → сообщить фактический SHA и push status. SHA только что создаваемого коммита не записывается внутрь этого же коммита. Можно записать его в следующем checkpoint или итоговом сообщении.

После смены задачи либо перегрузки контекста начать новую сессию с CURRENT и выбранной карточкой. Compact/new chat не восстанавливают пропущенную запись состояния и не пополняют квоту модели. Не переносить весь chat transcript в AGENTS.
