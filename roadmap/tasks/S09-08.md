## Baseline — что уже существует

todo уже хранится в отдельной коллекции, queries фильтруют userId. done принимает позицию текущего списка, clear удаляет только done. Нет отдельной Gmail связи или доказанного handling больших/concurrent списков.

## Не входит

Не вводить второй бот/очередь, не менять UI язык или provider без решения, не исполнять register/start/deploy и реальные Google/depot операции по одному разрешению редактировать код. OWNER-D01 неизменен: AI-ответы проверяет человек, auto-send нет; `/todo done` не approval email.

## Acceptance — критерии приёмки

1. Два Discord user ID не получают и не изменяют записи друг друга; userId всегда определяется handler, а не пользовательским текстом.
2. add/list сохраняет ожидаемый порядок; пустой/чрезмерный ввод и missing timestamp обработаны явно без огромного reply.
3. done с invalid/out-of-range number не меняет запись; concurrency между просмотром и выбором позиции имеет документированное безопасное поведение, не подтверждает случайную задачу.
4. clear удаляет только завершённые задачи текущего user, не pending checklist и не коллекцию tasks; частичный failure не выдаётся за полный успех.
5. Checklist не достигает depot/AI/Gmail; контент не вызывает mass mentions; done не считается email approval. Emulator tests не требуют live service account.
