## Не входит

Нет чтения реальных писем, недоказанной национальной схемы номера, подключения LLM или поддержки всех перевозчиков.

## Критерии приёмки

1. Один ожидаемый идентификатор, несколько идентификаторов и отсутствие идентификатора дают различные результаты.
2. Телефон, timestamp, quoted reference и случайная цифровая последовательность не становятся verified consignment без отдельного lookup.
3. Повтор одного номера в подписи и body дедуплицируется, но два разных номера не теряются через first match.
4. Пустой/слишком большой/нестроковый вход обработан явно; лимиты задаются как engineering defaults и проверяются на границе.
5. Функция остаётся чистой: без Gmail/Drive/depot calls, storage и логирования исходного письма.

## Контракт данных и побочных эффектов

Extraction возвращает candidates с причинами, а не право на отправку ответа или изменение доставки. Recipient/thread не выводятся из найденного номера.

Новый SQL/серверный стек не вводится: сохраняются Chrome + существующий Node bot + Firestore. Изменения config/queue/storage требуют явной совместимости и recovery; не создавать несуществующий src/storage по старому шаблону. Правила безопасности: [security](../../docs/security-and-privacy.md), [контракты](../../docs/contracts.md).
