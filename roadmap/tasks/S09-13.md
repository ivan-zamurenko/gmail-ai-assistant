# S09-13 — Короткий driver report для повторної доставки в Discord

**Мета:** оператор отримує приватний англомовний report, з якого водієві зрозуміло,
де зафіксовано доставку, яку фізичну посилку шукати та куди її передоставити.

## Baseline — перевірити перед початком

`bot/src/render.js` формує загальну `/find` картку: адреса/контакти, карта,
історія до 12 сканів, POD. Вона не є окремим driver report.
`src/depot/lookup.js` обирає POD останнього delivered event і GPS останнього
скану з координатами незалежно, серед усіх parcels. `src/queue/executor.js`
не зберігає спільний parcel/event ключ для POD і GPS. Помилка POD може зупинити
весь `/find`. Не будувати новий report поверх припущення, що ці дані збігаються.
Це результати статичного аналізу; звірити з актуальним кодом і dirty tree.

Прочитати AGENTS, CURRENT, WORKLOG, `docs/decisions.md`, `docs/SECURITY.md`,
`docs/SECURITY-WORKLOG.md`, `docs/TESTING.md`, `docs/queue-contract.md` та
`docs/discord-bot.md`. Зберегти існуючі `/find`, Administrator/ephemeral межі
й користувацькі зміни, особливо render/geo/lookup/executor.

## Погоджений зміст і макет

Мова report — англійська. Одна компактна колонка, без історії сканів, ANSI-таблиць,
внутрішніх статусів, debug-полів, email та іншого необов'язкового шуму.
Не змінювати загальну `/find` картку на урізаний driver report.

```text
Parcel recovery & redelivery
[Consignment number] · Parcel [physical parcel number]

Recorded delivery point
[GPS coordinates / Collection location unavailable]
Nearby Eircode: [approximate, only if available]
Delivered: [date and time of the selected delivery event]
Signed for by: [only if recorded for that event]

Deliver to
[Recipient / company]
[Full correct address]
[Correct Eircode]
Phone: [recipient phone, if available]

Open recorded delivery point: [Google Maps URL]
Route to correct address: [Google Maps driving URL]

[POD photo for the selected delivery event, separate attachment]
```

Позначати Eircode, отриманий reverse geocoding, як приблизний. GPS — місце
зафіксованої події, не доказ поточного місцеперебування. Відстань сама по собі
не доводить помилкової доставки. Без підтвердження оператором контексту
передоставлення не називати помилкову доставку доведеним фактом.
Відсутні необов'язкові поля пропускати; відсутність точки доставки повідомляти
явно та не створювати маршрут із GPS іншої події. Не вигадувати кількість parcels.

## Scope — межі й архітектура

- Agent: `bot/src/` — окремі невеликі модулі відбору даних/моделі report і
  Discord rendering; тонке підключення до handler; `test/bot/`.
- Extension contributor: `src/depot/lookup.js`, вузькі регресії `test/depot/` —
  зберегти зв'язок конкретної фізичної посилки, delivery event, GPS, POD і підпису.
- Лише integrator: `src/queue/executor.js`, обидва `contract.js`, `firestore.rules`
  за потреби, версії/locks, документація, CURRENT/state/evidence/WORKLOG.
- Provider виклики тримати поза чистим renderer; готова модель report не повинна
  залежати від Discord, щоб у майбутньому не дублювати правила для WhatsApp.
- Wire-зміни описати й узгодити між producer/consumer/rules; версіонувати при
  несумісності, не додавати довільні depot notes або зайві персональні поля.

Спочатку показати власнику точний вхід у функцію (команда чи дія в `/find`),
спосіб вибору parcel/event при неоднозначності та фінальний макет. Це ще відкриті
продуктові рішення; не вгадувати їх і не перепитувати вже погоджені мову/канал/зміст.

## Не входить

WhatsApp API, автоматичне надсилання водієві, публічні Discord-канали, зміна
статусу доставки чи дати в depot, AI-опис фото та автоматичне визначення вини.
Кнопка `Text for WhatsApp` — попередня пропозиція, не обов'язкова погоджена функція.
Врахувати ручне копіювання: повні URL можна перенести в WhatsApp; фото окремо.
Не запускати bot/register/deploy/live API як локальну перевірку. Для live-пілоту
потрібні відповідні G_DISCORD_ACCESS/G_TEST_ACCOUNTS/G_PRIVACY; вони не блокують
синтетичну розробку. S09-13 не входить автоматично в базовий пілот S09-12.

## Acceptance — критерії готовності

1. Report містить лише потрібні водієві дані з макета, англійською, без scan history;
   `/find` зберігає свою функцію, report доступний лише адміністратору приватно.
2. Ідентичність parcel і delivery event узгоджує GPS/POD/підпис/час. На fixture
   з двома parcels та пізнішим стороннім GPS нічого не змішується. Неоднозначність
   вимагає вибору оператора; відсутні докази не підміняються сусідньою подією.
3. Maps-посилання мають перевірені й URL-encoded точки: recorded GPS та правильна
   адреса/Eircode, `api=1`, для маршруту `travelmode=driving`. Приблизна reverse
   адреса не замінює GPS; текст не називає пряму відстань довжиною дороги.
4. Відсутні/недоступні POD або Maps не приховують корисний report. Довгі поля
   вкладаються в Discord limits без втрати ключового номера/адреси; layout
   читабельний на мобільному synthetic preview. Відмова Discord не повторює depot-дію.
5. Handler використовує спільну перевірену модель report, не дублює domain logic.
   У tests/logs/evidence немає реальних клієнтських даних, фото, credentials або
   session URL; контракти сумісні, продуктова версія підвищена для змінених artifacts.

## Test-first — мінімум, без дублювання

Перед зміною коду сформулювати очікування і написати тести на відсутню поведінку.
Зберегти наявні tests; не змінювати очікування заради GREEN. Мінімальні групи:

1. **Правильна доставка:** synthetic multi-parcel/event fixture доводить зв'язок
   доказів і endpoints обох Maps URL; неоднозначність не дає впевненого report.
2. **Неповні дані:** немає GPS/POD або provider відмовив — лишається правильний
   текст із чесною відсутністю даних, без підстановок чужих координат/фото.
3. **Discord output:** погоджені поля, без історії, довгі значення вкладаються
   в ліміти. Admission/delivery тести залежностей перевикористати, не дублювати.

Рекомендований новий файл — `test/bot/driverReport.test.js`; adapter coverage
додавати лише там, де потрібний ризик не перевіряється через цей файл. Спочатку
вузький RED → GREEN, потім affected regressions і project gate: lint, npm test,
build, git diff --check. Наявний валідний сценарій не ламати заради штучного RED.
