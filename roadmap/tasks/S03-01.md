## Не входит

Нет обхода login, расширения поиска на чужие depots, live scraping или предположения о стабильности непроверенных endpoint.

## Критерии приёмки

1. Фикстуры valid result, no results, несколько совпадений, login page и malformed HTML дают разные безопасные outcomes.
2. Успешный HTTP 200 с login form не считается verified consignment.
3. Изменённый selector/отсутствующее поле возвращает unsupported response, а не пустую успешную запись.
4. Сопоставление требует точного ожидаемого номера; чужой первый search result не принимается.
5. Serialized injected lookup проверен в изолированном контексте; session/query не появляется в error output.

## Test-first и команды

Сначала проверять 200-login и multiple-results fixtures: текущий permissive parser не должен пройти их как found.

```sh
node --test --import ./test/helpers/noNetwork.js test/depot/lookup.test.js test/depot/depotTarget.test.js test/depot/labelVerifier.test.js test/queue/executor.test.js test/bot/render.test.js
node tools/checks.mjs
```

Адаптація 2026-10-28: використано чинний lookup.test.js, три grouped cases і
inline synthetic DOM fixtures. Перевіряється serialized function у node:vm,
а не реальний HTML parser/browser. За owner offline-first/minimal-tests
домовленістю це рівень локальної приймальної перевірки; live HTML variants
залишені неперевіреними. Production changes лише lookup.js; depotMain business
policy і consumers не змінювались. Operational query збережено в envelope,
але error reason/logs не містять query/session/raw HTML. Повний контракт та
обмеження у docs/depot-contract.md; успішна projection перевірена focused suite.

## Последовательность реализации

1. Зафиксировать минимальный ожидаемый DOM без копирования реальной сессии.
2. Выделить parse outcomes и написать adverse fixtures.
3. Подключить структурированный результат к callers и проверить serialization.

## Контракт данных и побочных эффектов

Lookup POST может быть read-only по смыслу. Его authorization и response shape проверяются, но факт lookup не разрешает change-date.

Новый SQL/серверный стек не вводится: сохраняются Chrome + существующий Node bot + Firestore. Изменения config/queue/storage требуют явной совместимости и recovery; не создавать несуществующий src/storage по старому шаблону. Правила безопасности: [security](../../docs/security-and-privacy.md), [контракты](../../docs/contracts.md).
