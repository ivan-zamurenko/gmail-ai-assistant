## Не входит

Нет логина в рабочий Chrome profile, использования real depot session, broad host permission или подмены Chrome теста lint.

## Критерии приёмки

1. В чистом профиле загружен dist, а не source marker; popup и background действительно запускаются без missing asset/module errors.
2. Injected functions выполняются после сериализации в isolated test target, без недоступных outer imports.
3. Manifest host/permissions/CSP не расширяются для обхода test failure; test target scope задаётся контролируемо.
4. Close/reopen popup и restart worker не теряют journal state и не выполняют повторный effect.
5. Tests блокируют все реальные Google/depot/AI endpoints; наличие browser executable и успешные assertions записаны фактически.

## Test-first и команды

Перед изменением собрать конкретный failing browser scenario: например missing console artifact или lost closure. Нет Chrome — env_blocked, не реальный behavioral RED.

```sh
node --test test/browser/extension-smoke.test.mjs
```

Это целевая команда карточки: указанные product test files нужно создать при её выполнении. Их нет в исходном ZIP, и они не объявлены пройденными. Сначала подготовить harness по зависимостям. При изменении имени теста обновить карточку и evidence до заявления о GREEN.

После узкой проверки выполнить затронутые регрессии и обязательные lint/build проверки по [toolchain](../../docs/toolchain.md). Для injected code отдельно проверять serialization, для UI — реальный browser harness. Не выполнять real Gmail/Drive/depot/AI calls по одному разрешению редактировать код.

## Последовательность реализации

1. Выбрать browser harness по актуальной официальной документации при реализации.
2. Поднять synthetic local fixture и строгую network deny policy.
3. Запустить dist smoke/lifecycle/injection и сохранить очищенный evidence.

## Контракт данных и побочных эффектов

Browser smoke доказывает локальный runtime, но не Google OAuth, доступность intranet или permission на production mutations.

Новый SQL/серверный стек не вводится: сохраняются Chrome + существующий Node bot + Firestore. Изменения config/queue/storage требуют явной совместимости и recovery; не создавать несуществующий src/storage по старому шаблону. Правила безопасности: [security](../../docs/security-and-privacy.md), [контракты](../../docs/contracts.md).
