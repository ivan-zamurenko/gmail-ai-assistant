## Не входит

Нет redesign в React, сокрытия failures, auto-run после reopen или отображения клиентских данных в общей диагностике.

## Критерии приёмки

1. Queued, reading, preview, applying, partial, uncertain, cancelled и complete имеют различимый UI и не сводятся к Ready.
2. Счётчики основаны на unique items и подтверждённых effects; skipped/failed не суммируются как applied.
3. Повторное открытие popup восстанавливает job ID/status из runner, а не начинает новый run автоматически.
4. Ошибка одного item сохраняет результаты остальных и показывает доступное безопасное действие без blanket retry.
5. Длинные messages и быстрые изменения status не сбрасывают ввод/selection; sensitive data не дублируется в открытых logs.

## Test-first и команды

На browser fixture воспроизвести partial/uncertain и закрытие popup; false completed indicator должен дать RED.

```sh
node --test test/browser/popup-states.test.mjs
```

Это целевая команда карточки: указанные product test files нужно создать при её выполнении. Их нет в исходном ZIP, и они не объявлены пройденными. Сначала подготовить harness по зависимостям. При изменении имени теста обновить карточку и evidence до заявления о GREEN.

После узкой проверки выполнить затронутые регрессии и обязательные lint/build проверки по [toolchain](../../docs/toolchain.md). Для injected code отдельно проверять serialization, для UI — реальный browser harness. Не выполнять real Gmail/Drive/depot/AI calls по одному разрешению редактировать код.

## Последовательность реализации

2. Написать browser fixtures для transitions и reopen.
3. Обновить status rendering и retry/cancel affordances.

## Контракт данных и побочных эффектов

UI отображает domain state, а не выводит его из текста ошибки или disabled button. Browser test должен запускать расширение/страницу по выбранному harness, не только jsdom.

Новый SQL/серверный стек не вводится: сохраняются Chrome + существующий Node bot + Firestore. Изменения config/queue/storage требуют явной совместимости и recovery; не создавать несуществующий src/storage по старому шаблону. Правила безопасности: [security](../../docs/security-and-privacy.md), [контракты](../../docs/contracts.md).
