## Не входит

Нет внешнего log provider, загрузки реальных логов, изменения retention без G_PRIVACY или подавления всех ошибок.

## Критерии приёмки

1. Синтетические session/UID/token значения не встречаются в console, thrown message, popup text и evidence summary.
2. Ошибка сохраняет operation, code и безопасный status, достаточные для диагностики, но не полный URL с query.
3. Неожиданный HTML/JSON response и error body не печатаются сырым фрагментом; ошибки парсинга не обходят redaction.
4. Injected функция остаётся self-contained: helper редактирования не является недоступным outer import.
5. Положительные успешные сценарии не изменяют результаты lookup/сканера; негативные тесты проверяют каждый выходной канал.

## Test-first и команды

Передавать уникальные synthetic secret markers через ошибочные ответы и assert их отсутствие во всех captured outputs; исходные URL-containing ошибки дают RED.

```sh
node --test test/unit/redaction.test.mjs
```

Это целевая команда карточки: указанные product test files нужно создать при её выполнении. Их нет в исходном ZIP, и они не объявлены пройденными. Сначала подготовить harness по зависимостям. При изменении имени теста обновить карточку и evidence до заявления о GREEN.

После узкой проверки выполнить затронутые регрессии и обязательные lint/build проверки по [toolchain](../../docs/toolchain.md). Для injected code отдельно проверять serialization, для UI — реальный browser harness. Не выполнять real Gmail/Drive/depot/AI calls по одному разрешению редактировать код.

## Последовательность реализации

1. Перечислить реальные точки console/error/status вывода в затронутых модулях.
2. Написать leakage tests с уникальными маркерами и captured logger.
3. Заменить сырой detail безопасными кодами и проверить serialization boundary.

## Контракт данных и побочных эффектов

Logs — технические коды, не копии клиентских данных. Redaction применяется до логирования/отправки в UI. Это не обещание полного secret scanning всех файлов.

Новый SQL/серверный стек не вводится: сохраняются Chrome + существующий Node bot + Firestore. Изменения config/queue/storage требуют явной совместимости и recovery; не создавать несуществующий src/storage по старому шаблону. Правила безопасности: [security](../../docs/security-and-privacy.md), [контракты](../../docs/contracts.md).
