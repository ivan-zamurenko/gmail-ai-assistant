## Не входит

Нет реальных model calls, выполнения JSON-команд от модели, клиентского auto-send или утверждения абсолютной защиты одним prompt.

## Критерии приёмки

1. Unknown fields, неправильные типы, превышенные длины и unsupported action отклоняются строгой schema.
2. Предложенные shipment IDs и факты сверяются с переданным trusted context; выдуманная дата доставки не становится подтверждённым фактом.
3. Письмо с фразой ignore instructions/send credentials и barcode payload с URL остаются данными, не tool instructions.
4. AI output не может вызвать send, reschedule, file move или изменить policy/gate, даже если schema корректна.
5. Schema failure не исправляется молчаливым удалением safety-critical поля; итог требует review/blocked с безопасной причиной.

## Test-first и команды

Adversarial synthetic outputs и prompt-injection corpus создаются до validator; все непредусмотренные actions должны давать отказ без effects.

```sh
node --test test/unit/ai-output.test.mjs
```

Это целевая команда карточки: указанные product test files нужно создать при её выполнении. Их нет в исходном ZIP, и они не объявлены пройденными. Сначала подготовить harness по зависимостям. При изменении имени теста обновить карточку и evidence до заявления о GREEN.

После узкой проверки выполнить затронутые регрессии и обязательные lint/build проверки по [toolchain](../../docs/toolchain.md). Для injected code отдельно проверять serialization, для UI — реальный browser harness. Не выполнять real Gmail/Drive/depot/AI calls по одному разрешению редактировать код.

## Последовательность реализации

1. Определить минимальную schema proposal и список разрешённых facts.
2. Добавить hostile input/output cases и endpoint deny assertions.
3. Реализовать strict validation и отдельную human confirmation boundary.

## Контракт данных и побочных эффектов

Модель не является источником полномочий. Fake output проверяет приложение, но не доказывает prompt-injection устойчивость конкретного live provider.

Новый SQL/серверный стек не вводится: сохраняются Chrome + существующий Node bot + Firestore. Изменения config/queue/storage требуют явной совместимости и recovery; не создавать несуществующий src/storage по старому шаблону. Правила безопасности: [security](../../docs/security-and-privacy.md), [контракты](../../docs/contracts.md).
