Не вводить второй бот/очередь, не менять UI язык или provider без решения, не исполнять register/start/deploy и реальные Google/depot операции по одному разрешению редактировать код. OWNER-D01 неизменен: AI-ответы проверяет человек, auto-send нет; `/todo done` не approval email.

## Acceptance — критерии приёмки

1. Тест использует явно локальный Emulator/project и отказывается работать с production host; fixture seed и cleanup затрагивают только собственное пространство теста.
2. Назначенный authenticated UID читает и claims pending до expiresAt; другой UID и anonymous без нужного назначения не читают/не меняют task.
3. Browser не создаёт/не удаляет tasks, не читает/не меняет todos; попытка изменить command,args,requestedBy,executorUid при update отклоняется.
4. Expired pending -> cancelled разрешён только по условиям времени; terminal rewrite и повторный claim не проходят. Проверить границу времени, не только happy path.
5. Oversized summary/details, неверный execMs и non-map parcel отклоняются; факт, что nested parcel schema пока не проверяется rules, явно отражён и компенсирован отдельным validation plan, а не объявлен solved.

## Test-first и команды

До правки поведения создать выполняемый test по критериям и воспроизвести реальный дефект. Если исходная защита уже корректна, сохранить characterization и продемонстрировать чувствительность к контролируемой неверной fixture, не ломать приложение ради RED. Отсутствующая библиотека/Emulator/Chrome — env_blocked, не functional RED.

```sh
node --test test/queue/firestore-rules.test.mjs
```

Команду запускать после создания теста/подготовки зависимости; для S09-12 show только читает карточку. Затем затронутые регрессии, сохранённый `test/`, lint и нужный build по [toolchain](../../docs/toolchain.md). Не прогонять реальный bot startup как тест imports.

## Контракт данных и эффектов

Использовать существующие tasks/todos и rules. Emulator tooling/version зафиксировать в lock/config. Настоящий firebase deploy не входит в задачу. Admin bypass model проверяется отдельно от browser credentials.

Общие источники: [queue](../../docs/queue-contract.md), [Discord](../../docs/discord-bot.md), [security](../../docs/security-and-privacy.md). Различать выполнение бизнес-операции, terminal task, delivery reply и учёт процесса разработки.
