# Установка комплекта без потери существующей работы

> **Адаптація до робочого проєкту, 2026-10-23.** Поточний стан і пріоритет рішень: [LOCAL_BASELINE](docs/audit/LOCAL_BASELINE.md). Нижче збережено план комплекту v1.2; його вихідний ZIP і старі перевірки не є поточним checkout. Майбутні задачі не запускаються автоматично. Спілкування з власником — українською.


## Назначение и пределы

Комплект добавляет документацию, инструкции агентов и локальные валидаторы. Он не заменяет весь проект и не должен распаковываться поверх неизвестного рабочего дерева с подтверждением «заменить всё». `src/`, `manifest.json`, `package.json`, lockfile, `.git` и runtime-настройки не входят в поставку.

Единственный ожидаемый конфликт с исходным архивом — корневой `README.md`. На твоём компьютере после упаковки ZIP могли появиться и другие одноимённые файлы; сверка обязательна. Никакой автоматической очистки старых инструкций не предусмотрено.

## 1. Подготовить безопасную точку возврата

Распаковать комплект отдельно. В существующем репозитории выполнить `git status --short` и проверить ветку. Сохранить незакоммиченные изменения обычным способом проекта, не делать `reset --hard`, не удалять untracked files и не применять `stash` вслепую. Зафиксировать базовый SHA локально.

Если это только распакованный исходный ZIP, сначала определить, действительно ли внутри находится нужная `.git` и совпадает ли checkout с текущим репозиторием. Не инициализировать второй Git внутри первого. Не подключать remote из эталонного проекта.

## 2. Сравнить и перенести

Сопоставить корневые файлы и каталоги `.github/`, `.agents/`, `.workflow/`, `agent-config/`, `docs/`, `prompts/`, `roadmap/`, `tools/`, `checks/`. Скрытые каталоги начинаются с точки и могут не отображаться в Finder.

Новые пути можно добавить. Существующие файлы нужно объединить по смыслу. Для README сохранить исходную версию в истории Git либо в явно помеченном локальном historical-файле, затем заменить только после проверки ссылок и описаний. Старый `docs/TOOLING.md` не удалять: сначала пометить историческим отдельной задачей, поскольку его сведения о сборщике уже расходятся с кодом.

`.workflow/CURRENT.md` описывает **выпуск комплекта KIT-02**, а `state.json` содержит начальные todo-задачи до принятия проекта. Это не состояние твоего рабочего Git. Если уже есть актуальные checkpoint/state, не перезаписывать их. Перенести новые карточки и вручную согласовать ID/формат с существующим workflow.

## 3. Проверить комплект

Из корня, где находятся `tools/` и `roadmap/`, выполнить:

```sh
node tools/roadmap.mjs validate
node tools/check-docs.mjs
node --test tools/tests/*.test.mjs
node tools/roadmap.mjs next
```

Первые три команды должны завершиться с exit code 0. Последняя должна предложить S00-01 при неизменённом начальном state. Команды не работают с Gmail, Drive, depot, Git remote или API-ключами.

## 4. Подключить выбранного агента

Copilot: [COPILOT_SETUP_RU.md](COPILOT_SETUP_RU.md). Codex: [CODEX_SETUP_RU.md](CODEX_SETUP_RU.md). Примеры JSON/TOML находятся в `agent-config/` и не активируются автоматически. Они не должны заменять пользовательские настройки целиком.

Сначала проверить обнаружение инструкций запросом только на чтение. Не проверять подключение кнопкой реального сканирования или отправкой письма. Агент должен найти CURRENT, назвать S00-01 и объяснить, какие проверки приложения ещё отсутствуют.

## 5. Принять baseline и сделать ограниченный commit

Завершить S00-01. В staged diff должны быть только просмотренные документация и tooling. Полный тест приложения не подменять проверкой Markdown. Commit message взять из карточки, commit SHA записать после фактического создания. Push допустим только в отдельно подтверждённые remote и ветку.

## Откат комплекта

Отменить только собственный commit с документацией или восстановить конкретные пути из сохранённой версии. Не удалять каталоги целиком, если в них появились чужие изменения. Этот откат не меняет Chrome storage, OAuth, Drive и depot, поскольку комплект их не трогает. Если после установки уже запускались live-операции приложения, Git rollback их не отменяет.

## Обновление v1.1 -> v1.2 с bot baseline

Сначала сравнить docs/audit/GITHUB_BASELINE.md с настоящим checkout. Не использовать старое описание «бота нет», «worker только onInstalled», «npm test отсутствует» и «config из storage». Новая версия включает 12 S09 карточек, два pending gates, Discord/queue/runbook и адресную инструкцию.

Все прежние 41 task IDs сохранены. Если по v1.1 уже шла разработка, перенести только новые записи и reviewed изменения зависимостей, сохраняя фактические статусы/evidence/active_task. Не заменить state целиком: добавленная зависимость готовой задачи требует сверки и отдельного review, а не выдуманного done.

`.workflow/CURRENT.md` здесь — checkpoint выпуска комплекта, не состояние пользовательского Git. Существующий CURRENT сохранить в истории и объединить осмысленно. Baseline старого ZIP и исторические проверки остаются в docs/audit и checks; новый отчёт отдельно UPDATE_V1_2.

Runtime исходники из нового GitHub ZIP в этот архив не вложены. Не заменять bot/src, src/config, существующие docs/SECURITY.md/TEAM.md/TOOLING.md или реальные local.js файлами комплекта. Проверить инструкцию старых docs на конфликт и сохранить историю прежде редакции. Raw photo не переносится.

После merge выполнить graph/doc/tool tests. Это не запускает bot/register/Firestore deploy. Затем проверить discovery Copilot/Codex на read-only запросе с существующим ботом в контексте.
