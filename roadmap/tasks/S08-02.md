## Не входит

Нет публикации store, включения фото клиента, отправки repository archive вместо dist или смены extension identity ради удобства.

## Критерии приёмки

1. Артефакт содержит только требуемые runtime assets и manifest; source archive, .git, labels_example и secrets отсутствуют.
2. Manifest key/client identity сохраняются либо изменение явно отдельно одобрено; version согласована с release decision.
3. ZIP paths безопасны, нет path traversal/неожиданных symlinks; состав проверяется автоматическим allowlist.
4. Хеши и состав артефакта зафиксированы; clean rebuild различия объяснены, а не названы reproducible по одному запуску.
5. Console helper включён только если нужен утверждённому распространению; debug exports не попадают в package автоматически.

## Test-first и команды

Создать temporary build с запрещённым файлом и assert отказ упаковки, а не молчаливое включение приватного fixture.

```sh
node --test test/tooling/package.test.mjs
```

Это целевая команда карточки: указанные product test files нужно создать при её выполнении. Их нет в исходном ZIP, и они не объявлены пройденными. Сначала подготовить harness по зависимостям. При изменении имени теста обновить карточку и evidence до заявления о GREEN.

После узкой проверки выполнить затронутые регрессии и обязательные lint/build проверки по [toolchain](../../docs/toolchain.md). Для injected code отдельно проверять serialization, для UI — реальный browser harness. Не выполнять real Gmail/Drive/depot/AI calls по одному разрешению редактировать код.

## Последовательность реализации

1. Определить allowlist состава из build output.
2. Протестировать excluded files/path safety и manifest references.
3. Сформировать hash manifest и описать ручную проверку артефакта.

## Контракт данных и побочных эффектов

Package != published release. Права публикации и изменения version/identity требуют G_RELEASE; локальный артефакт не устанавливается пользователям автоматически.

Новый SQL/серверный стек не вводится: сохраняются Chrome + существующий Node bot + Firestore. Изменения config/queue/storage требуют явной совместимости и recovery; не создавать несуществующий src/storage по старому шаблону. Правила безопасности: [security](../../docs/security-and-privacy.md), [контракты](../../docs/contracts.md).

## Критерий завершения

Все сценарии выше проверены на указанном уровне; одна лишь проверка Markdown не закрывает product acceptance. Нет ослабленных expectations, пустых успешных suites и skip вместо обязательной проверки. В evidence сохранены точные команды, cwd, exit codes, граница synthetic/live, непроверенное и остаточный риск. Если не хватает решения или среды, записать blocked/env_blocked и конкретный следующий шаг; не ставить done.

## Review, commit и передача

Проверить `git status --short`, узкий diff и `git diff --check`; staging только просмотренных путей. Разрешение commit/push сверить отдельно. Предложенный subject:

```text
build(release): [S08-02] package only approved runtime assets
```

Evidence: `.workflow/evidence/S08-02.json`. Обновить существующие CURRENT/state, не заменять их шаблоном. Собственный SHA не записывать внутрь создаваемого коммита. В финале указать фактические RED/GREEN или честное N/A, commit/push status и один следующий task ID.

## Адаптация к bot baseline v1.2

Extension artifact не содержит bot/config/service account. Bot deploy и source bundle отдельны, оба locks сохранены. Отсутствующий файл ключа в ZIP не доказывает отсутствие inline secret в dist.
