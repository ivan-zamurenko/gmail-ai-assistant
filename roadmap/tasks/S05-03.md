## Не входит

Нет автоматического доступа к чужой отправке, отправки ответа, AI inference фактов доставки или нового CRM.

## Критерии приёмки

1. Один candidate с точным found lookup создаёт case context с source IDs и временем чтения, а не только произвольным summary.
2. Несколько candidates/несколько совпадений/lookup failure оставляют manual-review outcome без first-match automatic action.
3. Совпадение номера не доказывает право автора письма на чужую отправку; отсутствие подтверждённой связи не обходится parser результатом.
4. Изменение depot facts между preview и последующим действием обнаруживается по freshness check.
5. Case context не содержит depot session/Google token и не переносит raw HTML в AI payload по умолчанию.

## Test-first и команды

Synthetic messages с двумя отправками и несовпадающим lookup должны остаться неоднозначными; tests проверяют ноль downstream mutation calls.

```sh
node --test test/unit/case-context.test.mjs
```

Это целевая команда карточки: указанные product test files нужно создать при её выполнении. Их нет в исходном ZIP, и они не объявлены пройденными. Сначала подготовить harness по зависимостям. При изменении имени теста обновить карточку и evidence до заявления о GREEN.

После узкой проверки выполнить затронутые регрессии и обязательные lint/build проверки по [toolchain](../../docs/toolchain.md). Для injected code отдельно проверять serialization, для UI — реальный browser harness. Не выполнять real Gmail/Drive/depot/AI calls по одному разрешению редактировать код.

## Последовательность реализации

1. Определить source-linked context DTO с явными unknowns.
2. Написать ambiguity/freshness/authorization boundary cases.
3. Подключить parser и lookup adapters без нового автоматического reschedule.

## Контракт данных и побочных эффектов

Evidence и предлагаемый ответ отделены. Tenant/organization ограничения источников не выводятся из произвольного email body.

Новый SQL/серверный стек не вводится: сохраняются Chrome + существующий Node bot + Firestore. Изменения config/queue/storage требуют явной совместимости и recovery; не создавать несуществующий src/storage по старому шаблону. Правила безопасности: [security](../../docs/security-and-privacy.md), [контракты](../../docs/contracts.md).
