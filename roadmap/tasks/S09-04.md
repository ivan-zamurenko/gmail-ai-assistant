## Acceptance — критерии приёмки

1. Когда extension уже завершило задачу, editReply rejection не удаляет единственную копию результата и не вызывает повторное depot execution.
2. Успешная доставка подтверждается отдельно; cleanup идёт только по определённой политике, а не fire-and-forget удалением до reply.
3. После restart бота доступна безопасная сверка terminal result/delivery state по стабильному ID; повтор вывода не создаёт вторую task с новым external effect.
4. Timeout pending и timeout claimed остаются различимыми; неизвестный write outcome не считается failure с автоматическим retry.
5. Протокол новых ACK/retention fields описан для старого/нового bot и extension; tests используют synthetic retention, live сроки и данные остаются за G_PRIVACY. Нет бесконечного хранения full payload по умолчанию.
