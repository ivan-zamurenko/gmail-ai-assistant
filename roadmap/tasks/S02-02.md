## Не входит

Нет ручного выбора за оператора, threshold от AI, удаления спорной фотографии или автоматического перемещения disputed files.

## Критерии приёмки

1. Два разных consignment candidates не превращаются в однозначный known только из-за PDF417 priority или большего числа reads.
2. Одинаковый consignment с разными parcel identifiers сохраняет конфликт parcel, а не теряет его при группировке.
3. Lookup подтверждающий существование номера не снимает конфликт принадлежности barcode к изображению.
4. Preview выводит безопасное состояние ambiguous и список допустимых причин; автоматическая mutation для ambiguous отсутствует.
5. Один непротиворечивый candidate проходит прежний позитивный путь. Выбор ручного resolve и его UX остаются за G_DRIVE_POLICY.

## Test-first и команды

Synthetic decoder results с двумя номерами и отдельно двумя parcel одного номера должны воспроизвести потерю неоднозначности в исходной агрегации.

```sh
node --test test/unit/barcode-ambiguity.test.mjs
```

Это целевая команда карточки: указанные product test files нужно создать при её выполнении. Их нет в исходном ZIP, и они не объявлены пройденными. Сначала подготовить harness по зависимостям. При изменении имени теста обновить карточку и evidence до заявления о GREEN.

После узкой проверки выполнить затронутые регрессии и обязательные lint/build проверки по [toolchain](../../docs/toolchain.md). Для injected code отдельно проверять serialization, для UI — реальный browser harness. Не выполнять real Gmail/Drive/depot/AI calls по одному разрешению редактировать код.

## Последовательность реализации

1. Зафиксировать формат candidates с provenance без customer payload в логах.
2. Написать conflict cases и тест отсутствия Drive mutations.
3. Передавать ambiguity до scanner summary и сохранить независимый unambiguous path.

## Контракт данных и побочных эффектов

Консервативная остановка ambiguous apply — safety default, а не новое правило окончательного именования. Никакого выдуманного confidence score или silent first-candidate winner.

Новый SQL/серверный стек не вводится: сохраняются Chrome + существующий Node bot + Firestore. Изменения config/queue/storage требуют явной совместимости и recovery; не создавать несуществующий src/storage по старому шаблону. Правила безопасности: [security](../../docs/security-and-privacy.md), [контракты](../../docs/contracts.md).
