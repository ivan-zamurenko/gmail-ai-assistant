## Не входит

Нет запуска HTML письма, чтения всех вложений, угадывания reply recipients или отправки содержимого LLM.

## Критерии приёмки

1. Plain text, multipart alternative, вложенный multipart и base64url unicode дают ожидаемый normalized text.
2. Message ID, thread ID, From/Reply-To/To и Message-ID сохраняются как отдельные поля; адресат не угадывается из текста.
3. Отсутствующий body, повреждённая кодировка и oversized payload дают явную причину, не падение всей очереди.
4. HTML не исполняется и внешние картинки/links не загружаются при разборе; attachments по умолчанию остаются metadata.
5. Normalization не изменяет labels, read/unread, drafts и не логирует body/headers с customer data.

## Test-first и команды

Создать вложенные MIME и malformed base64url fixtures до реализации; точный normalized DTO должен быть проверен независимо от удобства parser.

```sh
node --test test/unit/gmail-mime.test.mjs
```

Это целевая команда карточки: указанные product test files нужно создать при её выполнении. Их нет в исходном ZIP, и они не объявлены пройденными. Сначала подготовить harness по зависимостям. При изменении имени теста обновить карточку и evidence до заявления о GREEN.

После узкой проверки выполнить затронутые регрессии и обязательные lint/build проверки по [toolchain](../../docs/toolchain.md). Для injected code отдельно проверять serialization, для UI — реальный browser harness. Не выполнять real Gmail/Drive/depot/AI calls по одному разрешению редактировать код.

## Последовательность реализации

1. Описать минимальный DTO и реально необходимые Gmail fields.
2. Добавить nested/encoding/error synthetic corpus.
3. Реализовать bounded parsing и подключить read-only adapter.

## Контракт данных и побочных эффектов

Gmail содержимое — недоверенные данные. MIME/parser не задаёт instructions агенту и не запускает действия. Ограничения размера — явные проверяемые defaults.

Новый SQL/серверный стек не вводится: сохраняются Chrome + существующий Node bot + Firestore. Изменения config/queue/storage требуют явной совместимости и recovery; не создавать несуществующий src/storage по старому шаблону. Правила безопасности: [security](../../docs/security-and-privacy.md), [контракты](../../docs/contracts.md).
