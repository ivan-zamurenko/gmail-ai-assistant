## Не входит

Нет установки неизвестных plugins, принудительного auto-approve, выбора самой дорогой модели или заявления об экономии credits без измерения.

## Критерии приёмки

1. В evidence названы продукт, версия клиента, режим/harness и корень workspace без приватных абсолютных путей.
2. UI References/diagnostics либо документированный механизм загрузки показывает применённые instructions; одного утверждения модели недостаточно.
3. Read-only запрос не изменяет файлы и Git; отдельная проверка объясняет текущую карточку и запрет live effects.
4. Codex config и VS Code settings проверены как разные слои; отсутствующая модель или платная квота не придумываются.
5. Если доступа к установленному агенту нет, статус env_blocked с конкретным следующим шагом; S01 локальные задачи не блокируются этим gate.

## Test-first и команды

Это проверка конфигурации/обнаружения, не TDD приложения. Отсутствие клиента — env_blocked. Нельзя фабриковать RED/GREEN интерфейса.

```sh
node tools/check-docs.mjs
```

Команда уже существует в комплекте. Она проверяет документы/tooling, а не заменяет ручную или внешнюю проверку, описанную ниже.

После узкой проверки выполнить затронутые регрессии и обязательные lint/build проверки по [toolchain](../../docs/toolchain.md). Для injected code отдельно проверять serialization, для UI — реальный browser harness. Не выполнять real Gmail/Drive/depot/AI calls по одному разрешению редактировать код.

## Последовательность реализации

1. Выбрать один фактически установленный инструмент и выполнить setup guide.
2. Сверить instruction discovery и ограничения read-only на безопасном запросе.
3. Записать доказательство без debug payload с секретами; оставить второй инструмент непроверенным при отсутствии доступа.

## Контракт данных и побочных эффектов

Примеры config не меняют разрешения сами. Сохранить существующие settings, approvals, model и бюджеты; подтвердить только реально наблюдённое.

Новый SQL/серверный стек не вводится: сохраняются Chrome + существующий Node bot + Firestore. Изменения config/queue/storage требуют явной совместимости и recovery; не создавать несуществующий src/storage по старому шаблону. Правила безопасности: [security](../../docs/security-and-privacy.md), [контракты](../../docs/contracts.md).

## Критерий завершения

Все сценарии выше проверены на указанном уровне; одна лишь проверка Markdown не закрывает product acceptance. Нет ослабленных expectations, пустых успешных suites и skip вместо обязательной проверки. В evidence сохранены точные команды, cwd, exit codes, граница synthetic/live, непроверенное и остаточный риск. Если не хватает решения или среды, записать blocked/env_blocked и конкретный следующий шаг; не ставить done.

## Review, commit и передача

Проверить `git status --short`, узкий diff и `git diff --check`; staging только просмотренных путей. Разрешение commit/push сверить отдельно. Предложенный subject:

```text
docs(agents): [S00-05] record instruction discovery evidence
```

Evidence: `.workflow/evidence/S00-05.json`. Обновить существующие CURRENT/state, не заменять их шаблоном. Собственный SHA не записывать внутрь создаваемого коммита. В финале указать фактические RED/GREEN или честное N/A, commit/push status и один следующий task ID.
